# LiveMap Phase 1: Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `npx livemap <dir>` indexes a project (files, symbols, imports), keeps that model live as files change, describes every change at the symbol level, and serves a first UI (file tree with symbols + inspector) that updates over a token-protected WebSocket.

**Architecture:** TypeScript ESM package. `src/engine` holds pure analyzers (tree-sitter WASM for structure, regex resolvers for imports) behind a `ProjectModel` that owns all file state; `src/engine/differ.ts` turns before/after models into `ChangeSummary`s; `src/engine/watcher.ts` (chokidar) feeds the model. `src/server` exposes HTTP + WebSocket on 127.0.0.1 with a per-run token. `ui/` is a Vite React app built into `dist/ui` and served by the server.

**Tech Stack:** Node ≥18, TypeScript 5.6, tsup 8, vitest 2, web-tree-sitter 0.25.10 + tree-sitter-wasms 0.1.13, chokidar 4, ignore 6, diff 7, ws 8; UI: Vite 5, React 18.3, Tailwind 3.4, Zustand 5, Shiki 1, Playwright for e2e.

**Spec:** `docs/superpowers/specs/2026-10-14-livemap-design.md` (sections 4, 5, 6, 10, 12, 13, 14). Visual reference: `docs/design/prototype.html`.

## Global Constraints

- Node 18+; ESM only (`"type": "module"`); no native modules.
- Runtime dependencies limited to: `chokidar`, `web-tree-sitter@0.25.10`, `tree-sitter-wasms@0.1.13`, `ignore`, `diff`, `ws`. (0.25.10 is required: 0.22.x cannot load the Dart grammar, verified 2026-10-14.)
- Server binds `127.0.0.1` only; every API and WebSocket request must carry the per-run token (`?t=` query or `x-livemap-token` header), else 401. The static UI shell (no project data) loads without it. There is no cookie: cookies ignore ports, so every server on 127.0.0.1 would receive it.
- `.env` files (`.env`, `.env.*` except `.example`/`.sample`/`.template`): key names only; values never stored, sent or logged.
- Files over 1 MB (1,048,576 bytes) are listed but not parsed (`flags.tooLarge`). Binary files (known extension or a NUL byte) are listed, not parsed (`flags.binary`).
- Index limit 25,000 files.
- Watcher debounce: 150 ms per file.
- Diff hunks truncated at 800 lines per change (`truncated: true`).
- All paths in models and messages are POSIX-style, relative to the project root.
- Performance: file save → UI updated under 500 ms (files under 5,000 lines); initial index of 5,000 files under 15 s.
- UI copy: no em dashes; US spelling ("license").
- No telemetry.

## Review Focus

1. **Half-written files.** Agents save files mid-edit with syntax errors. Expected: the file keeps its last good symbols and gets `flags.parseError`, and the UI shows a badge instead of an empty file. Pinned in Task 6.
2. **Atomic saves.** Editors and agents write a temp file then rename it over the target, or write several times in 100 ms. Expected: exactly one change event with the final content, and no phantom "deleted then created". Pinned in Task 8.
3. **Binary content without a binary extension** (e.g. a `.js` that is actually a compiled blob with NUL bytes, or a minified 3 MB bundle). Expected: listed with `binary`/`tooLarge`, never parsed, no crash, no hang. Pinned in Task 5.
4. **Paths with spaces, unicode, or Windows separators.** Expected: model keys are POSIX relative paths, and the UI and `/api/file` round-trip them. Pinned in Tasks 5 and 9.
5. **A file deleted and recreated, or a directory removed wholesale** (`rm -rf src/old`). Expected: every file under it is removed from the model, importers' links update, and one `deleted` change per file. Pinned in Tasks 6 and 8.

### Task 2: Tree-sitter loader and JS/TS/TSX symbols

**Files:**
- Create: `src/engine/parser.ts`, `src/engine/symbols/index.ts`, `src/engine/symbols/js.ts`
- Test: `tests/engine/symbols-js.test.ts`, fixtures `tests/fixtures/js/service.ts`, `tests/fixtures/js/Page.tsx`

**Interfaces:**
- Consumes: `Lang`, `CodeSymbol`, `GRAMMAR` (Task 1).
- Produces: `getParser(lang: Lang): Promise<Parser | null>` (parser.ts, caches per grammar, resolves wasm via `createRequire(import.meta.url).resolve('tree-sitter-wasms/out/tree-sitter-<g>.wasm')`, returns null if the grammar fails to load); `extractSymbols(lang: Lang, source: string): Promise<{ symbols: CodeSymbol[]; ok: boolean }>` (ok=false when there is no grammar, or when the tree's root `hasError` is true and no symbols were found); `flattenSymbols(symbols: CodeSymbol[]): CodeSymbol[]`.

Discover each grammar's node type names by printing a parsed fixture's tree.
