# LiveMap Phase 3: Domain Views Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** LiveMap extracts the project's API routes and screens, database schema, dependencies, env var names and stack. It shows them in three new center views (Schema, API, Stack) that update live as the agent writes code.

**Architecture:**
- **Analyzers.** Pure, pattern-based analyzers (`src/engine/domain/*`) run on each text file next to the symbol and import extraction. They fill the `routes`, `entities`, `env`, `deps` and `mounts` fields that phase 1 left empty. The phase 1 differ already turns those fields into change facts.
- **Domain index.** A server-side `DomainIndex` derives the project-wide picture from all FileModels:
  - routes with mount prefixes applied;
  - merged tables with relations;
  - which files use which tables;
  - detected stack, all deps, and all env names.
- **Delivery to the UI.** The index is sent as one throttled `domain` message, following the `usedBy` pattern. The UI adds a segmented center control with Activity, Schema (React Flow + ELK in a worker), API (request-flow lanes) and Stack views.

**Tech Stack:**
- Unchanged from phases 1-2.
- New UI dependencies, pinned exactly: `@xyflow/react@12.11.6` and `elkjs@0.12.0`.
- No new runtime dependencies in the CLI package.

**Spec:** `docs/superpowers/specs/2026-10-14-livemap-design.md`:
- §4 analyzers and data model;
- §5 "Stack-specific extraction" (the framework list is binding);
- §6 change descriptions;
- §10 Schema, API and Stack views, tab badges;
- §12 secrets;
- §13 performance;
- §15 one fixture per supported framework.

Visual reference: `docs/design/prototype.html`. See its `.tbl` table cards, `.lane-h` / `.ap` API lanes with `LANES = Routes, Handlers, Services, Tables`, the `stackv` / `.sgrid` / `.techs` Stack view, and the `[role=tab]` segmented control with `.cnt` badges.

## Global Constraints

- **Accuracy rule (spec §5):** structure is exact; routes and schema are pattern-based. Every route, entity, mount and env item carries its source `file` and `line`. The UI labels routes, schema links and "uses table" links as approximate where they come from name matching.
- **No new CLI dependencies, no native modules.** Analyzers are plain TypeScript over source text.
  - No regex may backtrack catastrophically: use only linear patterns, with no nested quantifiers over the same characters.
  - Analyzers only run on files the model already reads as text (≤ 1 MB).
- **Performance (spec §13).**
  - The existing perf test (`npm run test:perf`, 5,000 files) must stay under 15 s total and under 500 MB RSS with analyzers enabled.
  - A save must still reach the UI in under 500 ms.
  - The domain index is rebuilt at most once per second (trailing throttle, like `usedBy`).
- **Secrets (spec §12).** `.env` files contribute key names only, through the existing secret read path, and their values are never read into analyzers. `.env.example`, `.env.sample` and `.env.template` are ordinary text; only their keys are extracted.
- **Analyzer gating.** An analyzer runs only on the languages and file names it declares, so the regex cost per file stays small.
- **UI rules.**
  - No em dashes in UI copy; US spelling.
  - Light and dark themes.
  - Respect `prefers-reduced-motion`.
  - Phone width works.
  - Match the prototype.
- **Route `method` values:**
  - an uppercase HTTP verb;
  - `ANY` (all methods);
  - `PAGE` (a web page route such as Next.js `page.tsx` or SvelteKit `+page.svelte`);
  - `SCREEN` (a mobile screen).
- **Route `path` format.** Use `:param` style for parameters (`[id]` → `:id`, `{id}` → `:id`, `<int:id>` → `:id`). Paths start with `/` and have no trailing slash except the root `/`.

## Review Focus

1. **Half-written files** (the agent is mid-edit: unbalanced braces, an unterminated string or template, a 1 MB minified bundle). Expected: no analyzer throws or hangs, the file keeps its other facts, and the analysis stays under about 50 ms. Pinned in Task 1 (registry error isolation and a timing test) and in each analyzer task's malformed-input test.
2. **Many frameworks in one repo** (a monorepo with a Next.js web app, an Express API, a FastAPI service and Prisma plus SQL migrations). Expected: every analyzer contributes, there is no cross-talk (Express patterns never fire on Python), and the Stack view lists them all. Pinned in Task 10's polyglot fixture.
3. **Same table defined in several places** (a Prisma model and a SQL migration for the same table, or `CREATE TABLE` plus later `ALTER TABLE ADD COLUMN` in another file). Expected: one table in the Schema view, with fields merged and sources listed. Pinned in Task 6.
4. **Large schemas and route sets** (150 tables, 600 routes). Expected: the Schema and API views stay responsive (layout off the main thread, render capped with "Show all"), and the index rebuild stays under 100 ms. Pinned in Tasks 6, 8 and 9.
5. **Live edits** (a route renamed, a table field added, a dependency bumped while the view is open). Expected:
   - the change card shows the plain-language fact;
   - the view updates in place without existing table cards jumping;
   - the new item is highlighted green;
   - the tab badge bumps.

   Pinned in Tasks 7, 8 and 10.

```ts

export interface Mount { prefix: string; spec: string; target: string | null; line: number; framework: string }  // target = resolved root-relative file
export interface Field { name: string; type: string; line?: number; pk?: true; required?: true; unique?: true; fk?: { table: string; field: string }; relation?: { model: string; many: boolean } }
export interface Entity { name: string; table: string; orm: string; file: string; line: number; fields: Field[]; partial?: true }   // partial = ALTER fragment

// Dep: + line?: number
```
  Existing code that builds `Route` objects (the differ and its tests) is updated for the new required fields.
- `src/engine/domain/index.ts`:
  - `export interface DomainFacts { routes: Route[]; entities: Entity[]; env: string[]; deps?: { deps: Dep[]; scripts?: Record<string,string> }; mounts: Omit<Mount,'target'>[] }`
  - `export interface Analyzer { name: string; applies(rel: string, lang: Lang): boolean; run(rel: string, lang: Lang, text: string): Partial<DomainFacts> }`
  - `export const ANALYZERS: Analyzer[]`
  - `export function analyzeFile(rel: string, lang: Lang, text: string, analyzers = ANALYZERS): DomainFacts`
  - `analyzeFile` merges the results in registry order: routes are sorted by line then method; env is unique and sorted; entities and mounts keep their order.
  - Each analyzer runs in its own try/catch. A throw drops only that analyzer's facts and logs once per analyzer name to stderr, as `livemap: analyzer <name> failed on <rel>: <message>`.
- `src/engine/imports.ts`: `export function resolveSpecifier(from: string, lang: Lang, spec: string, ctx: ImportCtx): string | null`. It uses the same resolution as `extractImports` for JS/TS (relative, aliases, extensions, index files) and Python (relative and absolute dotted). Other languages return null.
- `ProjectModel.build`:
  - Text files get `{...analyzeFile(...)}` merged in, and each mount gets `target = resolveSpecifier(rel, lang, spec, ctx)`.
  - `relink()` re-resolves mount targets as well. A changed mount target counts as a change for `touched`.
  - `.env` secret files keep `env` from the secret read path, unchanged.
- `deps.ts` (`Analyzer` named `deps`) parses these manifests:

  | Manifest | Ecosystem (`eco`) | What is read |
  |---|---|---|
  | `package.json` | `npm` | deps; devDependencies with `dev: true`; `scripts` |
  | `requirements*.txt` | `pypi` | `name==1.2` / `>=` / bare names; comments and `-r` / `-e` skipped |
  | `pyproject.toml` | `pypi` | `[project] dependencies` array and `[tool.poetry.dependencies]` table, minus `python` |
  | `go.mod` | `go` | `require` lines and blocks; `// indirect` included |
  | `Cargo.toml` | `cargo` | `[dependencies]`, `[dev-dependencies]` (dev), string and table versions |
  | `Gemfile` | `gem` | `gem 'x', '~> 1'` |
  | `composer.json` | `composer` | require, require-dev (dev); `php` and `ext-*` skipped |
  | `build.gradle(.kts)` | `maven` | `implementation`, `api`, `testImplementation` (dev), `"g:a:v"` and `group:, name:, version:` forms; name `g:a` |
  | `pubspec.yaml` | `pub` | dependencies, dev_dependencies (dev); `sdk: flutter` entries named `flutter` with version `sdk` |
  | `Podfile` | `cocoapods` | `pod 'X', '~> 1'` |

  Each dep carries `line`. A missing version is `''`. Invalid JSON yields no deps (no throw).
- `env.ts` (`Analyzer` named `env`):
  - Code usages are read from these forms:
    - JS/TS: `process.env.X`, `process.env['X']`, `import.meta.env.X`, `Deno.env.get('X')`.
    - Python: `os.environ['X']`, `os.environ.get('X')`, `os.getenv('X')`.
    - Go: `os.Getenv("X")`, `os.LookupEnv("X")`.
    - Rust: `env::var("X")`, `std::env::var("X")`.
    - Ruby: `ENV['X']`, `ENV.fetch('X')`.
    - PHP: `getenv('X')`, `$_ENV['X']`, `env('X')` in Laravel.
    - Kotlin and Java: `System.getenv("X")`.
  - Keys of `.env.example`, `.env.sample` and `.env.template` are read with the existing `envKeys()` helper.
  - Names must match `/^[A-Za-z_][A-Za-z0-9_]*$/`. Dynamic keys are ignored.

### Task 2: JS/TS routes and mounts

**Files:**
- Create: `src/engine/domain/routes-js.ts`; register it in `ANALYZERS`
- Test: `tests/engine/domain/routes-js.test.ts`, fixtures under `tests/fixtures/domain/routes/{express,fastify,hono,koa,nest,next-app,next-pages,sveltekit}/`

**Interfaces:**
- Consumes: Task 1 `Analyzer`, `DomainFacts`, `lineAt`, `maskCommentsAndStrings`, `normPath`.
- Produces: an analyzer named `routes-js`, applying to typescript, tsx, javascript and svelte, plus file-based routing by path.

**Rules:**
- **Express and Koa.**
  - `(app|router|server|api|<ident from express() or Router() or new Router()>).(get|post|put|patch|delete|options|head|all)(<string literal>, ...)` maps to method upper-case (`all` becomes `ANY`), the path, and `handler`. The handler is the last identifier argument, or `inline` for an inline function. Use `framework: 'express'`, or `'koa'` when the file imports `@koa/router` or `koa-router`.
  - `router.route('/x').get(h).post(h2)` produces 2 routes.
  - `express.Router({...})` prefix options are ignored.
- **Fastify.** `fastify.get('/x', ...)` uses the same form with `framework: 'fastify'`. `fastify.route({ method: 'GET', url: '/x', handler })` is read too; a method array produces one route per method.
- **Hono.** `app.get('/x', ...)` and `app.on('GET', '/x', ...)` give `framework: 'hono'`. `new Hono().basePath('/api')` prefixes routes in the same file.
- **Mounts:**
  - `app.use('/api', ordersRouter)` gives `{prefix:'/api', spec}`, where `spec` is the import specifier the identifier came from (`import ordersRouter from './routes/orders'`, `import { router as ordersRouter }`, or `const ordersRouter = require('./routes/orders')`).
  - Hono `app.route('/api', orders)` and Fastify `register(import('./x'), { prefix: '/api' })` / `register(x, { prefix })` mount the same way.
  - When the identifier is not imported, there is no mount.
- **NestJS.**
  - `@Controller('orders')` on a class sets the prefix (also `@Controller({ path: 'orders' })`).
  - Methods decorated `@Get(':id')`, `@Post()`, etc. become routes, with handler = method name and `framework: 'nest'`.
- **Next.js app router:**
  - A file `app/**/route.(ts|js)` (also under `src/app/`) gives one route per exported `GET|POST|PUT|PATCH|DELETE|HEAD|OPTIONS` function or const. The path comes from the folders, minus `(group)` segments and `@slot` segments. `[id]` becomes `:id`, and `[...slug]` and `[[...slug]]` become `:slug*`.
  - A file `app/**/page.(tsx|jsx|ts|js)` gives method `PAGE`, kind `page`, and handler = default export name if any.
  - `framework: 'next'`.
- **Next.js pages router:**
  - `pages/api/**.(ts|js)` gives method `ANY`, the path `/api/...`, and `framework: 'next'`. `index` becomes the parent path.
  - Other `pages/**.(tsx|jsx|ts|js)` files give `PAGE`, excluding `_app`, `_document` and `_error`.
- **SvelteKit.** `src/routes/**/+server.(ts|js)` gives exported verb functions. `src/routes/**/+page.svelte` gives `PAGE`. Path rules match Next (`(group)` removed, `[id]` becomes `:id`, `[...rest]` becomes `:rest*`). `framework: 'sveltekit'`.
- **File-based route paths** come from the path relative to the `app`, `pages` or `src/routes` directory found anywhere in the file path, so monorepos like `apps/web/app/...` work.

### Task 3: Routes for Python, Go, JVM, Ruby, PHP, and mobile screens

**Files:**
- Create: `src/engine/domain/routes-other.ts`, `src/engine/domain/screens.ts`; register both
- Test: `tests/engine/domain/routes-other.test.ts`, `tests/engine/domain/screens.test.ts`, fixtures under `tests/fixtures/domain/routes/{fastapi,flask,django,go-http,gin,chi,spring,rails,laravel}/` and `tests/fixtures/domain/screens/{expo,react-navigation,gorouter}/`

**Interfaces:** consumes Task 1. Produces the analyzers `routes-other` and `screens`.

**Rules:**
- **FastAPI.**
  - `@app.get('/x')` / `@router.post('/x')` decorators on `def` or `async def` give handler = function name.
  - `APIRouter(prefix='/orders')` in the same file prefixes that router's routes.
  - `app.include_router(orders.router, prefix='/api')` and `app.include_router(router)` give mounts, with spec = the module the name came from (`from .routers import orders` gives spec `.routers.orders`; `from app.routers.orders import router` gives `app.routers.orders`).
  - `@app.api_route('/x', methods=['GET','POST'])` gives one route per method.
  - `framework: 'fastapi'`.
- **Flask.**
  - `@app.route('/x', methods=['POST'])` gives the listed methods, defaulting to GET.
  - `@bp.get('/x')` is read too.
  - `Blueprint('orders', __name__, url_prefix='/orders')` prefixes routes in the same file.
  - `app.register_blueprint(orders_bp, url_prefix='/api')` gives a mount.
  - `<int:id>` becomes `:id`.
  - `framework: 'flask'`.
- **Django.** In `urls.py`:
  - `path('orders/<int:pk>/', views.detail)` gives `ANY /orders/:pk`, handler `views.detail`.
  - `re_path(r'^x/$', v)` gives the raw pattern stripped of `^` and `$`.
  - `include('orders.urls')` with a prefix gives a mount with spec `orders.urls`.
  - `framework: 'django'`.
- **Go.**
  - net/http 1.22: `mux.HandleFunc("GET /orders/{id}", h)` / `http.HandleFunc("/x", h)` (no method gives `ANY`), `{id}` becomes `:id`, `framework: 'go-http'`.
  - gin: `r.GET("/x", h)`, plus `g := r.Group("/api")` prefixing calls on `g` in the same file, `framework: 'gin'`.
  - chi: `r.Get("/x", h)`, plus `r.Route("/api", func(r chi.Router) { r.Get(...) })` with the nested prefix, `framework: 'chi'`.
- **Spring** (Java and Kotlin).
  - A class-level `@RequestMapping("/orders")` sets the prefix.
  - `@GetMapping("/{id}")`, `@PostMapping`, and `@RequestMapping(value="/x", method=RequestMethod.POST)` are read, with the handler = the next method name.
  - `framework: 'spring'`.
- **Rails** (`config/routes.rb`).
  - `get '/x', to: 'orders#index'` gives handler `orders#index`.
  - `resources :orders` gives the 7 REST routes: index, show, new, create, edit, update, destroy. Paths are `/orders`, `/orders/:id`, `/orders/new` and `/orders/:id/edit`; PATCH is used for update.
  - `resources :orders, only: [:index, :show]` filters them.
  - `namespace :api do ... end` gives the `/api` prefix.
  - `framework: 'rails'`.
- **Laravel** (`routes/*.php`).
  - `Route::get('/x', [OrderController::class, 'index'])` gives handler `OrderController@index`.
  - `Route::resource('orders', OrderController::class)` gives the 7 REST routes.
  - `Route::prefix('api')->group(function () { ... })` prefixes routes in the same file.
  - Files under `routes/api.php` get the `/api` prefix (Laravel convention).
  - `framework: 'laravel'`.
- **Screens.** All are `method 'SCREEN'`, `kind 'screen'`.
  - Expo Router: files under `app/` in a project with `expo-router` imported anywhere in that file, or with `_layout.tsx` beside it. Same path rules as Next, plus `index` becomes the parent. `_layout` and `+not-found` are excluded. `framework: 'expo-router'`.
    - **Ruling:** an `app/**/page.tsx` file is Next; any other `app/**/*.tsx` that has a sibling `_layout.tsx` (checked by the Task 6 index rather than the per-file analyzer) is Expo. So the per-file analyzer emits Expo screens for `app/**/*.tsx` files whose own text imports `expo-router`, or that are named `_layout.tsx` (no route), and Task 6 promotes siblings of a `_layout.tsx`.
  - React Navigation: `<Stack.Screen name="Orders" component={OrdersScreen} />` gives path `Orders` (no leading slash for named screens) and handler `OrdersScreen`, for any `X.Screen`. `framework: 'react-navigation'`.
  - GoRouter: `GoRoute(path: '/orders', builder: ...)` with nested `routes:` paths joined. `framework: 'gorouter'`.

### Task 4: Schema for SQL, Prisma, Drizzle, TypeORM, Mongoose

**Files:**
- Create: `src/engine/domain/schema-sql.ts`, `src/engine/domain/schema-js.ts`; register both
- Test: `tests/engine/domain/schema-sql.test.ts`, `tests/engine/domain/schema-js.test.ts`, fixtures under `tests/fixtures/domain/schema/{sql,prisma,drizzle,typeorm,mongoose}/`

**Interfaces:** consumes Task 1. Produces `Entity` objects with `file` = rel, `line` = declaration line, and `Field.line`.

**Rules:**
- **SQL** (lang `sql`, plus any file with a `CREATE TABLE` inside a SQL string in JS/TS/Python/Go migrations; restrict non-SQL files to paths containing `migration`).
  - `CREATE TABLE [IF NOT EXISTS] [schema.]"name" ( ... )` gives `name` = table, `orm: 'sql'`.
  - Column definitions give the type (first type token, upper-cased), with:
    - `pk` from `PRIMARY KEY` inline or a table constraint;
    - `required` from `NOT NULL` or a pk;
    - `unique` from `UNIQUE`;
    - `fk` from `REFERENCES t(col)` or `FOREIGN KEY (c) REFERENCES t(col)`.
  - `ALTER TABLE t ADD [COLUMN] c TYPE ...` gives an `Entity` with `partial: true` and those fields.
  - `DROP TABLE` is ignored here; it is reflected by removal when the CREATE disappears.
  - Quoted identifiers use `"`, backticks or `[]`.
- **Prisma** (`*.prisma`).
  - `model X { ... }`: the table is `@@map("t")` or X.
  - Fields: `name Type`, with `?` meaning not required and `[]` meaning a many relation. `@id` and `@unique` set flags.
  - `@relation(fields: [userId], references: [id])` sets `relation {model: 'User', many: false}` on the relation field, and `fk {table: <User's table>, field: 'id'}` on `userId`. The table name is resolved within the same file; otherwise the model name is used.
  - Enum types stay as the type string.
  - `orm: 'prisma'`.
- **Drizzle.**
  - `export const orders = pgTable('orders', { id: serial('id').primaryKey(), userId: integer('user_id').references(() => users.id), ... })` (also `mysqlTable` and `sqliteTable`).
  - Name = the const name, table = the string. Field name = the object key; type = the builder fn name.
  - `.primaryKey()` sets pk, `.notNull()` sets required, `.unique()` sets unique, `.references(() => users.id)` sets `fk {table:'users'(const resolved to table string in-file), field:'id'}`.
  - `orm: 'drizzle'`.
- **TypeORM.**
  - `@Entity('orders')` / `@Entity()` class: table = the arg or class name.
  - Fields come from `@Column(...)`, `@PrimaryGeneratedColumn()` / `@PrimaryColumn()` (pk), and `@ManyToOne(() => User)` / `@OneToMany(() => Item, ...)` (relation, many for OneToMany or ManyToMany).
  - The type is the TS type annotation.
  - `orm: 'typeorm'`.
- **Mongoose.**
  - `new Schema({ name: String, total: { type: Number, required: true }, user: { type: Schema.Types.ObjectId, ref: 'User' } })` together with `model('Order', orderSchema)` gives entity `Order`, with table = `mongoose.pluralize` style lowercase plural (`orders`).
  - `ref` sets `relation {model, many:false}`; an array `[{ type: ObjectId, ref }]` sets many.
  - `orm: 'mongoose'`.

### Task 5: Schema for SQLAlchemy, SQLModel, Django, Room, SwiftData

**Files:**
- Create: `src/engine/domain/schema-other.ts`; register it
- Test: `tests/engine/domain/schema-other.test.ts`, fixtures under `tests/fixtures/domain/schema/{sqlalchemy,sqlalchemy-mapped,sqlmodel,django,room,swiftdata}/`

**Rules:**
- **SQLAlchemy classic.**
  - A class with `__tablename__ = 'orders'` gives fields from `x = Column(Integer, primary_key=True)`, `Column(String, nullable=False)` (required), `unique=True`, and `ForeignKey('users.id')` (fk).
  - `relationship('User')` gives a relation; `uselist` and list annotations set many.
- **SQLAlchemy 2.0 `Mapped`.**
  - `id: Mapped[int] = mapped_column(primary_key=True)`; `Mapped[Optional[str]]` means not required.
  - `user_id: Mapped[int] = mapped_column(ForeignKey('users.id'))`.
  - `items: Mapped[list['Item']] = relationship()` is many.
  - `orm: 'sqlalchemy'`.
- **SQLModel.** `class Order(SQLModel, table=True)`: fields from annotations and `Field(primary_key=True, foreign_key='user.id')`. The table is the lowercased class name unless `__tablename__` is set. `orm: 'sqlmodel'`.
- **Django** (`models.py` or any file under a `models/` dir).
  - `class Order(models.Model)`: the table is `<app>_<lowercase model>`, where app = the dir containing models.py. `Meta.db_table` overrides it.
  - Fields: `models.XField(...)` with type `XField`.
  - `ForeignKey('User', ...)` / `ForeignKey(User, ...)` gives a relation, plus an fk to that model's table (resolved in-file, else the lowercased name).
  - `primary_key=True` sets pk, `null=True` means not required, `unique=True` sets unique. An implicit `id` pk field is added when no field is pk.
  - `orm: 'django'`.
- **Room** (Kotlin and Java).
  - `@Entity(tableName = "orders") data class Order(@PrimaryKey val id: Long, ...)`.
  - `foreignKeys = [ForeignKey(entity = User::class, parentColumns = ["id"], childColumns = ["userId"])]` gives the fk.
  - A nullable type `?` means not required.
  - `orm: 'room'`.
- **SwiftData.** `@Model final class Order { var id: UUID; var items: [Item] = []; var user: User? }`: a stored `var` is a field, an array of a @Model type is a many relation, an optional means not required, and `@Attribute(.unique)` sets unique. Table = the class name. `orm: 'swiftdata'`.

Also recorded are lowerCamel model accessors (`prisma.order`, `db.order`) and table names in quotes (`'orders'`, `"orders"`, `` `orders` ``).
