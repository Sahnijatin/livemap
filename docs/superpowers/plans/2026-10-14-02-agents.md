# LiveMap Phase 2: Agents Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** LiveMap shows what each AI agent is doing and why (prompts, messages, tool calls, commits), links every file change to the agent action that caused it, and lets the user flag a file or pause the agent from the UI. Covered agents: Claude Code, Codex CLI, Cursor, and cloud builders through git.

**Architecture:** New `src/agents/` package. Pure normalizers turn each agent's hook payloads and transcripts into one `AgentEvent` shape. An `AgentHub` owns sessions and the event ring. `Attribution` links `ChangeSummary`s to events. `Control` answers the hooks' "may I proceed?". A tiny self-contained hook script (copied to `~/.livemap/bin/`) forwards hook stdin to the running server, which it finds through a per-project runtime file. `livemap init` writes each agent's hook config. The UI gains an Activity view, agent chips, Pause, Flag, and "Why it changed".

**Tech Stack:** Same as phase 1 (Node ≥18 ESM TypeScript, vitest, React 18 + Zustand UI, Playwright). No new runtime dependencies. `git` is invoked through `child_process.execFile` when present.

**Spec:** `docs/superpowers/specs/2026-10-14-livemap-design.md` sections 4 (`AgentEvent`), 7 (Agents: setup, contributions, attribution, steering), 10 (Activity view, chips, Pause, Flag, Live session panel), 12, 14. Visual reference: `docs/design/prototype.html` (Activity tab, hero "Now" card, feed items, agent chips, flag box, "Why it changed").

## Hook facts (verified 2026-10-14; implementers rely on these)

- **Claude Code:** project config `.claude/settings.local.json`, shape `{"hooks":{"<Event>":[{"matcher":"*","hooks":[{"type":"command","command":"…","timeout":5}]}]}}`. The stdin JSON has `session_id, transcript_path, cwd, hook_event_name`, plus `tool_name, tool_input, tool_use_id` on tool events and `prompt` on UserPromptSubmit. Exit code 2 on PreToolUse blocks the tool and feeds stderr to Claude. The transcript is JSONL: each line has `type` (`user` | `assistant` | `attachment` | `system` | `summary` …), `uuid`, `timestamp`, `sessionId`, `cwd` (on most lines), `isSidechain`, `isMeta` and `message`. Assistant `message.content` holds `text`, `thinking` and `tool_use {id,name,input}` blocks. User `message.content` is a string (a prompt) or an array holding `text` or `tool_result {tool_use_id, content (string | [{type:'text',text}]), is_error}`. Prompts can contain `<system-reminder>…</system-reminder>` and `<command-…>` tags.
- **Codex CLI:** project config `.codex/hooks.json`, shape `{"hooks":{"<Event>":[{"hooks":[{"type":"command","command":"…","timeout":5}]}]}}` (omitting `matcher` matches everything). Project hooks run only after the user trusts them via `/hooks`. The stdin JSON has `session_id, transcript_path, cwd, hook_event_name, model`, plus `turn_id, tool_name, tool_use_id, tool_input` on PreToolUse and PostToolUse, `tool_response` on PostToolUse, `prompt` on UserPromptSubmit, and `last_assistant_message` and `stop_hook_active` on Stop. `tool_input.command` holds the shell command for `Bash`, and for `apply_patch` it holds the patch text (`*** Update File: <path>` / `*** Add File:` / `*** Delete File:` lines). **Exit 2 on PostToolUse replaces the tool result and on Stop forces Codex to continue, so the hook may exit 2 only on PreToolUse.**
- **Cursor:** project config `.cursor/hooks.json`, shape `{"version":1,"hooks":{"<event>":[{"command":"…"}]}}`. Every event receives `conversation_id, generation_id, hook_event_name, workspace_roots, transcript_path, model`. Per event: `preToolUse {tool_name, tool_input, tool_use_id, cwd}`, `postToolUse {tool_name, tool_input, tool_output (JSON string), tool_use_id, cwd, duration}`, `beforeShellExecution {command, cwd}`, `afterShellExecution {command, output, duration}`, `afterFileEdit {file_path, edits[{old_string,new_string}]}`, `beforeSubmitPrompt {prompt}`, `afterAgentResponse {text}`, `afterAgentThought {text}`, `stop {status}`. A deny is `{"permission":"deny","agent_message":"…","user_message":"…"}` on stdout. Exit 2 is equivalent to a deny for `preToolUse` and `beforeShellExecution`.

## Global Constraints

- Node 18+, ESM, no native modules, no new runtime dependencies.
- If LiveMap is not running, every agent behaves exactly as without it: the hook exits 0 within 300 ms when no runtime file exists, and within 2.5 s at worst when the server does not answer.
- The hook exits 2 only for **PreToolUse** (Claude, Codex) and **preToolUse / beforeShellExecution** (Cursor), and only when the server says block. For every other event it always exits 0.
- Runtime file: `~/.livemap/run/<sha1(realpath root)>.json` = `{root, port, token, pid}`, mode 0600, removed on clean exit. A hook may only use it if `pid` is alive.
- `/hook` requires the per-run token (`x-livemap-token` header) and is subject to the same Host check as every other route.
- Pause message (exact): `The user paused this session in LiveMap. Stop and wait for their instructions.`
- Flag message (exact prefix): `The user flagged this in LiveMap:` followed by one line per flag: `- <target or "Project">: <note>`.
- Attribution windows: exact = a tool event whose target paths include the file, from 10 s before the change to 5 s after it (late events back-fill). Likely = any event from a session active in the last 15 s. Otherwise none ("outside an agent").
- Session idle after a stop event or 60 s without events. Event ring: last 2,000 events; `hello` carries the last 500 events.
- Tool output stored in events is truncated to 4,000 chars. Message text is never truncated below 4,000 chars.
- `.env` values must never enter an event: tool inputs and outputs that mention a secret file path keep the path but drop file contents (`Write`/`Edit` inputs for secret paths become `{file_path}` only).
- Git: HEAD polled every 3 s; `--pull` default interval 15 s, using `git pull --ff-only`. Git commands run with a 10 s timeout and never prompt (`GIT_TERMINAL_PROMPT=0`).
- UI copy: no em dashes; US spelling ("license").

## Review Focus

1. **Server not running or stale runtime file** (LiveMap closed with kill -9). Expected: the hook exits 0 quickly and the agent is unaffected. Pinned in Task 6 (dead pid, unreachable port, timing assertions).
2. **Huge or odd payloads:** a 2 MB tool output, a binary-ish tool response, or malformed JSON on stdin. Expected: the hook never crashes the agent, the server truncates or ignores, and the UI stays responsive. Pinned in Tasks 3 and 6.
3. **Several agents or sessions at once** (two Claude sessions plus Cursor in the same project). Expected: events are kept per session, attribution picks the session that touched the file, and the chips show both. Pinned in Tasks 4 and 5.
4. **A transcript file that is rotated, truncated or still being written mid-line.** Expected: no duplicated or lost events, and partial lines wait for completion. Pinned in Task 2.
5. **Re-running `livemap init` and then `init --remove`** on configs the user already has hooks in. Expected: idempotent; the user's own hooks are untouched; `--remove` restores the exact prior content minus LiveMap entries. Pinned in Task 8.

### Task 5: Attribution

**Files:**
- Create: `src/agents/attribution.ts`
- Test: `tests/agents/attribution.test.ts`

**Interfaces:**
- Consumes: `AgentHub` (`recent`, `'event'`), `ChangeSummary`, `Attribution`.
- Produces: `class Attributor extends EventEmitter { constructor(hub: AgentHub, opts?: { exactBeforeMs?: 10000, exactAfterMs?: 5000, likelyMs?: 15000 }); attribute(change: ChangeSummary, now?: number): Attribution | undefined; stop(): void }`. It emits `'late'` with `(changeId: number, attribution: Attribution)` when a tool event arriving within `exactAfterMs` upgrades a change that was unattributed or only `likely`.
  - Exact: the most recent `tool_start` or `tool_end` whose `paths` include `change.path`, within the window.
  - Likely: the most recently active session.
  - `intent`: the text of that session's last `message` event at or before the change, and after that session's last `prompt` (if there is no message since the prompt, the prompt text prefixed with `Asked: `), capped at 500 chars.
- [ ] **Step 1: Failing tests.**
  - An Edit tool event on `src/a.ts` 2 s before the change gives `confidence: 'exact'` and the intent is the preceding message.
