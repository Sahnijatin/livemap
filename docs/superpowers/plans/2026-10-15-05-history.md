# LiveMap Phase 5: History, Timeline, Export and AI Summaries Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Everything LiveMap shows is recorded per project. A timeline scrubber can rewind the whole UI to any moment, and that history survives restarts. `livemap export` writes one self-contained HTML replay. Optional AI summaries add one-line explanations of files and changes, using the user's own provider key.

**Architecture:** The server already broadcasts every UI-visible fact as a `ServerMessage`, so history records that stream.
- **Recording:** a `HistoryStore` appends each broadcast message, except `hello` and `indexing`, to a per-project JSONL log with a sequence number. A full `hello`-shaped snapshot is written at every run start and every 500 events.
- **Reconstruction:** a shared pure reducer (`applyMessage`) rebuilds the state at any `seq` from the nearest snapshot. The UI already applies the same messages, so live view, rewind and export run through one code path (spec §4).
- **Summaries:** a `Summarizer` (queue, disk cache, monthly token cap, Anthropic/OpenAI/Ollama over `fetch`) produces summaries. They are broadcast and recorded as ordinary messages.

**Tech Stack:**
- Unchanged.
- New UI dev dependency, pinned exactly: `vite-plugin-singlefile@2.3.0` (verify this version exists and is ≥ 2 weeks old when installing, otherwise pin the newest release older than 2 weeks and record it).
- No new CLI runtime dependencies (`node:zlib`, `node:crypto` and global `fetch` only).

## Global Constraints

- **Storage location:** `~/.livemap/projects/<sha1(realpath root)>/`, or `LIVEMAP_HOME` when set (the same rule `src/agents/runtime.ts` uses).
  - Files: `events-<runId>.jsonl` (one per run; `runId` = ISO start time with `:` replaced by `-`), `snapshots/<seq>.json.gz`, `index.json`.
  - Directory mode 0700, file mode 0600.
- **Event record:** one JSON line `{"seq":N,"at":<ms>,"run":"<runId>","msg":<ServerMessage>}`. `seq` increases monotonically across runs, starting at 1.
  - Recorded types: `files`, `change`, `usedBy`, `domain`, `agentEvent`, `session`, `control`, `attribution`, `summary`, `fileSummary`.
  - Never recorded: `hello`, `indexing`, `history`.
- **Snapshots:** written at each run start (after the initial scan, when the server becomes ready) and every 500 events. The content is the `hello` message shape (`ProjectState`), gzip-compressed.
- **Cap:** 200 MB per project by default (`LIVEMAP_HISTORY_MB` overrides it). When over the cap, the oldest run's event file and its snapshots are deleted until the total is under the cap. The current run is never deleted, so a single run larger than the cap keeps only its newest snapshot plus the tail after it.
- **Secrets:** history contains only what the UI already received, so `.env` values never appear. Summarizer requests never include secret files (`flags.secret`), binary files or files over 1 MB.
- **Store write failure** (spec §14):
  - The live UI continues unchanged.
  - Every client gets `{type:'history', history:{enabled:false, error:"…"}}` and shows the banner "History is unavailable: <short reason>". Exact copy: `History is unavailable` followed by `: ` and the reason.
  - Recording stops for the rest of the run, and the failure is logged once to stderr.
- **Summaries are off by default.**
  - **Opt-in:** they are enabled only when `~/.livemap/config.json` has `"summaries": {"enabled": true, …}` or the CLI is started with `--summaries`. An API key in the environment alone never enables them. This is ruling R1, below.
  - **Providers:**
    - `anthropic`: `POST https://api.anthropic.com/v1/messages`, headers `x-api-key` and `anthropic-version: 2023-06-01`, default model `claude-haiku-5-5`.
    - `openai`: `POST https://api.openai.com/v1/chat/completions` with Bearer auth, default model `gpt-6-luna`.
    - `ollama`: `POST <url>/api/chat` with `stream:false`, default URL `http://127.0.0.1:11434`. The model is required in config.
  - **Keys:** config `apiKey`, else `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`. Keys are never logged, recorded or sent to the UI.
  - **Monthly token cap:** 2,000,000 tokens (config `monthlyTokenCap`). Usage is stored in `~/.livemap/usage.json` as `{ "month": "YYYY-MM", "tokens": N }`. When the cap is reached, summaries stop with status `cap` until the month rolls over.
  - **Cache:** `~/.livemap/cache/summaries/<sha256(provider|model|promptVersion|input)>.json`.
- **Exact UI copy** (no em dashes, US spelling):
  - Timeline: `LIVE`, `REWOUND`, and the button "Back to live".
  - Rewound banner: `Viewing <time>. Changes made since then are hidden.`
  - Summary block heading: `In plain English`.
  - Summary fallback label: `In the agent's words`.
  - Export warning: `This export contains source code for <n> files. Share it only with people who may see this code.` (`--no-code` removes code and this warning).
- **Read-only while rewound:** the Flag box, Pause and pin-dragging are disabled, with the tooltip "Back to live to make changes".
- **Performance:**
  - Recording adds ≤ 1 ms per message on the broadcast path. Writes are buffered and flushed at least every 250 ms or every 256 KB, whichever comes first.
  - `stateAt(seq)` returns within 300 ms for a project with 50,000 events (snapshots every 500 events).
  - The ticks endpoint returns bucketed data no larger than 64 KB.
  - Activity's first-paint chunk stays within the phase 4 budget (+10 kB gzip over JS 72.29 / CSS 13.61), plus at most 3 kB gzip for the timeline.

## Review Focus

1. **Crash mid-write** (LiveMap killed with kill -9 while appending, leaving a half line at the end of the JSONL, or a half-written snapshot). Expected:
   - On the next start the partial line is ignored and truncated, and a bad snapshot is skipped in favor of an older one.
   - `seq` continues after the last good event.
   - The timeline loads.

   Pinned in Task 2.
2. **Files changed while LiveMap was not running** (the user edits code between runs). Expected:
   - Rewinding into the previous run shows that run's state.
   - The first point of the new run shows the newly scanned state, not a replay of the old run, because of the run-start snapshot.
   - The timeline shows a run boundary marker.

   Pinned in Tasks 2, 3 and 4.
3. **Scrubbing while the agent keeps working.** Expected:
   - The rewound view never moves while live messages arrive; they are not applied while rewound.
   - "Back to live" restores the exact current live state, including everything that happened while rewound.
   - Rapid thumb drags issue at most one state request per 120 ms, and the last one wins.

   Pinned in Task 4.
4. **The summarizer under failure:** no key, a 401, a 429 storm, an offline network, a 30 s hang, or the cap reached. Expected:
   - No crash and no stuck UI.
   - At most 2 concurrent requests, a 20 s timeout, and backoff on 429/5xx with at most 3 retries.
   - A status the user can see in the Stack view (`off`, `ready`, `working`, `error: <reason>`, `cap reached`).
   - Agent-words fallbacks keep showing.

   Pinned in Tasks 5 and 6.
5. **Export of a large history** (50,000 events, 2,000 files). Expected:
   - The export finishes in under 10 s and the file is under 60 MB. Events are stored compactly and gzip-compressed, then decoded in the browser with `DecompressionStream`.
   - The file opens offline from `file://` with no network requests.
   - Embedded JSON is escaped against `</script>` injection, because file contents can contain it.

   Pinned in Task 7.

### Task 2: History store

**Files:**
- Create: `src/history/store.ts`, `src/history/paths.ts`
- Test: `tests/history/store.test.ts`

**Interfaces:**
- `projectDir(root: string, home = process.env.LIVEMAP_HOME ?? ~/.livemap): string`.
- `class HistoryStore`:
  ```ts
  static open(root: string, opts?: { home?: string; capMb?: number; snapshotEvery?: number /* 500 */; now?: () => number }): Promise<HistoryStore>  // scans existing runs, repairs a truncated tail, builds the index
  startRun(state: ProjectState): Promise<void>      // new runId, writes a snapshot at the next seq boundary (snapshot seq = last seq, run marker)
  append(msg: ServerMessage, at?: number): number   // returns seq; buffers; throws never (errors -> onError)
  flush(): Promise<void>; close(): Promise<void>
  info(): { enabled: boolean; first: number; last: number; firstAt: number; lastAt: number; runs: { id: string; firstSeq: number; lastSeq: number; startAt: number }[]; bytes: number; error?: string }
  ticks(buckets: number, from?: number, to?: number): { from: number; to: number; buckets: { seq: number; at: number; counts: Record<'prompt'|'message'|'tool'|'change'|'commit'|'other', number> }[]; runStarts: number[] }
  messages(from: number, to: number, limit?: number): { seq: number; at: number; msg: ServerMessage }[]
  stateAt(seq: number): Promise<ProjectState & { seq: number; at: number }>
  onError: (e: Error) => void
  ```
- **Tick kinds** come from the message:
  - an `agentEvent` of type prompt is `prompt`; message or thinking is `message`; tool_start or tool_end is `tool`; commit is `commit`;
  - a `change` message is `change`;
  - everything else is `other`.
- **Index:** the in-memory index holds per-event `seq`, `at`, `file` and `byte offset` in compact typed arrays. It is persisted to `index.json` on close and rebuilt by scanning if missing or stale.
- **Snapshots** are gzip JSON. A snapshot that fails to parse is skipped (**Review Focus 1**).
- **Cap enforcement** runs on open and after every 5 MB written (Global Constraints).

### Task 5: Summarizer engine

**Files:**
- Create: `src/summarize/config.ts`, `src/summarize/providers.ts`, `src/summarize/summarizer.ts`
- Test: `tests/summarize/config.test.ts`, `tests/summarize/providers.test.ts`, `tests/summarize/summarizer.test.ts`

**Interfaces:**
- **Config:** `loadSummaryConfig(opts: { env: NodeJS.ProcessEnv; home?: string; flag?: boolean }): SummaryConfig | { disabled: true; reason: 'off' | 'no-key' | 'bad-config' }`.
  - `SummaryConfig = { provider: 'anthropic'|'openai'|'ollama'; apiKey?: string; model: string; url?: string; monthlyTokenCap: number }`.
  - **Provider choice:**
    1. config `provider`;
    2. else `anthropic` if `ANTHROPIC_API_KEY` is set;
    3. else `openai` if `OPENAI_API_KEY` is set;
    4. else `ollama` only if config gives a `url`.
  - **Enable rule:** see Global Constraints.
- **Providers:** `callProvider(cfg, prompt: { system: string; user: string; maxTokens: number }, fetchImpl = fetch, signal?): Promise<{ text: string; inputTokens: number; outputTokens: number }>`.
  - Exact endpoints and headers are in Global Constraints. Parse each provider's response format:
    - Anthropic: `content[0].text` and `usage.input_tokens` / `usage.output_tokens`.
    - OpenAI: `choices[0].message.content` and `usage.prompt_tokens` / `usage.completion_tokens`.
    - Ollama: `message.content`, `prompt_eval_count` and `eval_count`.
  - Throws a `ProviderError { status, retryable }`, where 429 and 5xx are retryable.
- **Summarizer:** `class Summarizer extends EventEmitter { constructor(cfg, opts: { home, fetchImpl?, now?, concurrency?: 2, timeoutMs?: 20000 }); status(): SummaryStatus; summarizeFile(file: FileModel, text: string): Promise<string | null>; summarizeChange(change: ChangeSummary, file: FileModel | null): Promise<string | null>; stop() }`.
  - `SummaryStatus = { state: 'off'|'ready'|'working'|'error'|'cap'; provider?; model?; usedTokens: number; capTokens: number; month: string; error?: string }`.
  - Emits `'status'`.
  - **Prompt version** constant `PROMPT_VERSION = 1`.
  - **File summary prompt.**
    - System: "You explain source files to developers in one or two plain sentences. No markdown. Describe what the file does and how it fits in."
    - User: the path, language, the symbol list (names and signatures), and the first 300 lines or 12,000 chars of text, whichever is smaller.
    - `maxTokens` 120.
  - **Change summary prompt.**
    - System: "You describe a code change in one plain sentence under 20 words. No markdown."
    - User: the path, the facts (added, removed and modified symbols, routes, tables, deps), and the hunks capped at 4,000 chars.
    - `maxTokens` 60.
    - Only for changes with at least one symbol, route or entity change (spec §9).
  - **Skipping:** files with `secret`, `binary` or `tooLarge` flags, or a lang of `secret`, are never sent; the method returns null.
  - **Cache:** looked up before any request and written after a success. A cache hit costs 0 tokens.
  - **Usage** is persisted after each call and compared to the cap before each call. If `used + estimate > cap`, the state becomes `cap` and nothing is sent. The estimate is chars / 4 plus `maxTokens`.
  - **Queue and retries:**
    - Concurrency 2, a 20 s timeout via `AbortController`, and up to 3 retries with exponential backoff (1 s, 2 s, 4 s) on retryable errors.
    - A non-retryable error (401, 403, 400) sets the state to `error: <status> <short message>` and pauses the queue for 60 s.
    - Responses are trimmed and cut to 300 chars.

**Interfaces:**
- `buildExport(root: string, opts: { home?: string; session?: string; code: boolean; uiHtml: string }): Promise<{ html: string; files: number; events: number }>`.
  - **Scope:**
    - Default: the whole stored history.
    - `--session <id>`: the events of that agent session, plus changes attributed to it, plus `files`/`domain`/`usedBy`/`control` messages within the session's time span (from its first to last event). The initial state is `stateAt(first seq - 1)`.
  - **Payload:** `{ version: 1, root name (not the absolute path), exportedAt, initial: ProjectState, messages: [seq, at, msg][], code?: Record<path, string> }`.

    - `code` holds the current contents of files touched in the exported range, read through `readForModel` (never secret, binary or files over 1 MB).
  - **Absolute paths:** the exported state replaces `root` with the project name. Absolute paths elsewhere, such as session `cwd` and `transcriptPath`, are reduced to their path relative to the root, or to their base name.
- **UI export mode:**
  - The page detects `#livemap-data` and decodes it with `DecompressionStream('gzip')`.
  - It starts rewound at the end state, with the timeline showing all messages and Play available.
  - There is no WebSocket and no API calls. `/api/file` is replaced by the embedded code, and when absent the UI shows "Code not included in this export".
  - The toolbar shows "Replay" in place of the live status.
  - Pause, Flag and agent controls are hidden.
- **Single-file build:** `vite build --config vite.export.config.ts`.
  - Code splitting and dynamic imports are inlined.
  - The ELK worker is inlined (`?worker&inline`).
  - Fonts are inlined as data URIs.
  - The output must contain no `src="http` or `href="http`, excluding the license comment URLs inside inlined JS.
- **CLI:**
  - Usage: `livemap export [dir=.] [--session ID] [--no-code] [--out FILE]`.
  - The default output is `livemap-<name>-<YYYYMMDD-HHmm>.html` in the current directory.
  - It works without a running server, reading the store directly.
  - It prints the exact warning when code is included, then the output path and size.
  - Exit code 1 when there is no history: "No history recorded for this project yet. Run livemap here first."

## Rulings made while planning

- **R1:** An API key in the environment alone never enables summaries. Explicit opt-in is required (config `enabled: true` or `--summaries`). Spec §12 says "nothing leaves the machine except optional summarizer calls to the provider the user configured", and many developers have `ANTHROPIC_API_KEY` set globally. Cost if wrong: one extra opt-in step.
- **R2:** Config `url` overrides any provider's base URL, for tests and proxies.
- **R3:** History records the server's message stream rather than a separate event model, so the live view, rewind and export share one reducer (spec §4).
- **R4:** Past file contents are not stored. Rewound CodeView shows current code with a notice. Export embeds the current contents of touched files. This keeps history small. Cost if wrong: code views in old states are not exact.
- **R5:** `--session` in export means an agent session id. The default exports the whole history.
