# LiveMap Phase 4: Full UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The production UI matches the approved prototype. It gains the live Map (files grouped in tinted folder regions, Folders / Files / Functions detail levels, live glow on the file being written, springs for new files, self-drawing links, Follow agent), a ⌘K palette across files, symbols, routes and tables, the motion system, and responsive layouts at every width.

**Architecture:**
- **Map model and layout.** A pure `mapModel.ts` turns `files`, `usedBy`, recent changes and agent state into map nodes and edges for each detail level. `mapLayout.ts` places them stably: ELK runs once per new folder set, in the worker phase 3 built. New files take a free slot near the file they import or are imported by. User-moved nodes stay pinned per project.
- **Map rendering.** `MapView.tsx` renders the model with React Flow (already a dependency) and custom node components that match the prototype `.node`, `.folder` and `.nsrow`.
- **Palette.** The ⌘K palette is built on `cmdk`.
- **Motion.** Motion uses `framer-motion` for enter, exit and layout transitions (spec §10 Implementation), plus CSS for the existing micro-animations. Everything respects `prefers-reduced-motion`.

**Tech Stack:**
- Unchanged, plus `framer-motion@13.4.6` and `cmdk@1.1.1` (exact pins, both released at least two weeks ago).
- `@xyflow/react@12.11.6` and `elkjs@0.12.0` are reused from phase 3.

**Spec:** `docs/superpowers/specs/2026-10-14-livemap-design.md` (§10 UI is binding: Layout, Visual language, Motion principles, Responsive, Implementation; §13 Map performance; §15 end-to-end with screenshots in light and dark).

**Visual reference:** `docs/design/prototype.html`. The relevant parts are:
- the toolbar: `.projsel`, `.agentchip`, `.now`, `.pillbtn.search` with `.kbd ⌘K`;
- the center head: `.tabs` with Map as the second tab, `.mini-seg#zoomSeg` Folders / Files / Functions, the `.toggle#followBtn` Follow switch;
- the Map world: `.folder`, `.node` and its states `.live` (amber ring plus sheen), `.isnew` (NEW tag), `.sel`, `.flagged` and `.fnz` (Functions level with `.nsrow` new and changed tints);
- edges: `linearGradient#gfresh` green to blue for new links;
- `.zoomctl`, the `.cv-hint` text, and `.palette#palette` with `#pinput` / `#pres`.

## Global Constraints

- **UI copy:** no em dashes; US spelling. Labels and hints follow the prototype wording: "Drag to pan · ⌘ + scroll to zoom · click a card to inspect"; "Search everything"; palette placeholder "Search files, functions, routes, tables…".
- **Easing (spec §10):**
  - Movement uses `cubic-bezier(.32,.72,0,1)`.
  - Selection and toggles use a gentle spring (framer-motion `{ type: 'spring', stiffness: 380, damping: 32 }`).
  - Layout moves use critically damped interpolation (framer-motion spring with `bounce: 0`).
  - `prefers-reduced-motion: reduce` turns every animation into an instant state change. This covers framer-motion via `MotionConfig reducedMotion="user"` plus explicit checks for camera moves.
- **Layer colors are fixed** (spec §10): purple Interface, blue API, indigo Server, teal Logic, pink Validation, orange Data. Green means new, orange means happening now, red means flagged or blocked.
- **Map stability** (spec §10):
  - Existing nodes never reshuffle when new ones arrive. Their relative order and folder never change.
  - The only automatic movement allowed is a vertical push-down to make room when a folder region grows. That movement is animated with critically damped interpolation.
  - User-moved nodes stay pinned. Pins are saved per project in `localStorage` under `livemap:pins:<project root>` (try/catch everywhere; the map works without storage).
- **Map performance** (spec §13):
  - Pan and zoom hold 60 fps with 500 file nodes. The Task 9 measured budget is median frame ≤ 16.7 ms, p95 ≤ 25 ms during a scripted pan on the 500-file fixture in Chromium.
  - Above 500 code files, the Map opens at the Folders level. The Files and Functions levels then render only expanded folders, shown with the notice "Large project: showing folders. Open a folder to see its files."
- **Bundle:** the Map and palette load lazily, so Activity's first-paint chunk grows by at most 10 kB gzip over the phase 3 baseline (measure and record).
- **Responsive breakpoints** (spec §10):
  - **Wide, ≥ 1280 px:** three columns.
  - **Medium, 1080–1279 px:** narrower panels.
  - **Below 1080 px:** the sidebar and inspector become slide-over panels opened from the toolbar.
  - **Phone, ≤ 640 px:** icon-only tabs, a condensed toolbar (agent chip names and the search label hidden, the search button icon-only), single-column content, and no horizontal page scroll at 360 px.
- **Accessibility:**
  - Every interactive element is keyboard reachable with a visible focus ring.
  - The palette is a dialog with focus trap and return.
  - Map nodes are focusable buttons with accessible names.
- No new runtime dependencies in the CLI package. `.env` values never appear (unchanged).

## Review Focus

1. **A burst of 40 new files in 3 seconds while the Map is open and Follow is on** (an agent scaffolding a project). Expected:
   - existing nodes never jump sideways;
   - each new file springs in from the file it connects to, or from its folder center;
   - the camera eases to the latest file without jitter, at most one camera move per 400 ms;
   - no frame stalls over 100 ms.

   Pinned in Tasks 3 and 5, and in the Task 9 e2e.
2. **The user drags a node, then the agent edits that file and adds a neighbor.** Expected:
   - the dragged node stays where the user put it (pinned) across live updates and a page reload;
   - "Reset layout" in the map menu clears pins.

   Pinned in Tasks 3 and 4.
3. **A 5,000-file repo.** Expected:
   - the Map opens at Folders with the large-project notice;
   - expanding one folder renders only that folder's files;
   - the palette searches all files and symbols with keystroke latency ≤ 50 ms (index built once per `files` change, off the keystroke path).

   Pinned in Tasks 2, 6 and 9.
4. **Resizing across breakpoints, or rotating a phone, with a slide-over open.** Expected:
   - no stuck scrim;
   - the panel closes when the layout becomes wide;
   - focus is restored;
   - no horizontal scroll at 360 px.

   Pinned in Task 8.
5. **Reduced motion.** Expected:
   - no transitions, springs, sheens or camera easing;
   - state still updates, and Follow still moves the camera, instantly.

   Pinned in Tasks 5 and 7.

### Task 2: Map model

**Files:**
- Create: `ui/src/map/mapModel.ts`
- Test: `ui/src/map/mapModel.test.ts`

**Interfaces:**
```ts
export type Level = 'folders' | 'files' | 'functions';
export interface MapFolder { id: string /* 'dir:<path>' */; path: string; label: string; layer: Layer; files: string[]; counts: { files: number; symbols: number; routes: number; tables: number }; isNew: boolean }
export interface MapFile { id: string /* file path */; folder: string; label: string; layer: Layer; symbols: number; rows: { name: string; kind: SymbolKind; tag?: 'new' | 'changed' }[]; isNew: boolean; isLive: boolean; isFlagged: boolean }
export interface MapEdge { id: string; source: string; target: string; weight: number; isNew: boolean }
export interface MapGraph { level: Level; folders: MapFolder[]; files: MapFile[]; edges: MapEdge[]; large: boolean }
export interface MapInput { files: Record<string, FileModel>; recent: Record<string, LiveBadge>; changes: ChangeSummary[]; flags: Flag[]; target: string | null; helloEdges: Set<string> }
export function buildMap(input: MapInput, level: Level, expanded: Set<string>): MapGraph
export const LARGE_PROJECT = 500;
```
- **Which files appear.** Only code files go on the map: files with a non-`other`/`text`/`json`/`yaml`/`toml` lang, or files with symbols. Markdown, config and lockfiles do not. Binary and secret files are excluded.
- **Folders** are the file's directory. Files in the root use folder id `dir:` with label "Project root".
- **Layer.** A folder's `layer` is the most common layer among its files, with ties broken by `LAYER_ORDER`.
- **Edges by level:**
  - At `files` and `functions`, each local import becomes one edge, `source` = importer and `target` = imported file, with `weight` 1.
  - At `folders`, edges are aggregated per folder pair (self-pairs dropped), and `weight` is the import count.
- **New edges.** An edge is `isNew` when its id is not in `helloEdges` (the baseline captured at hello, same idea as phase 3's baselines). Edge ids are `<source>-><target>`, and `dir:` ids at the folders level.
- **Rows.**
  - At `functions` each file carries up to 8 top-level symbol rows (flattened like the tree), tagged `new` or `changed` from its latest change via the existing `cachedTags`.
  - At `files`, `rows` is `[]`.
- **Flags and live state.** `isFlagged` means the file has an undelivered or delivered flag targeting it. `isLive` means `path === target`.
- **Large projects.** `large` is true when there are more than `LARGE_PROJECT` code files. In that case, at `files` and `functions` only files of folders in `expanded` are included, and edges are only between included files.
- **Ordering.** Output is sorted deterministically: folders by path, files by path.
- **Purity.** The function is pure, and is memoized by callers.

### Task 3: Stable map layout and pins

**Files:**
- Create: `ui/src/map/mapLayout.ts`, `ui/src/map/pins.ts`
- Test: `ui/src/map/mapLayout.test.ts`, `ui/src/map/pins.test.ts`

**Interfaces:**
- Constants:
  - `FILE_W = 220`, `FILE_H = 64` (files level);
  - functions-level height `= 64 + 24 × rows`;
  - `FOLDER_PAD = 20`, `FOLDER_HEAD = 44`, `GAP = 16`, `COLS_PER_FOLDER = 3`;
  - folder-level card `250 × 120`.
- `placeMap(graph: MapGraph, prev: Positions, pins: Pins, run: ElkRun): Promise<Positions>`, where `Positions = { folders: Map<string, Rect>; files: Map<string, Pos> }`:
  1. **Folder order** is computed by ELK `layered` (direction RIGHT) on the folder graph, only when the set of folder ids differs from `prev`. That happens on first layout or when a folder is added or removed.
     - Existing folders keep their columns and order.
     - A new folder takes ELK's position if it is free. Otherwise it goes at the end of the column ELK put it nearest to.
     - Reuse the phase 3 `workerRun`, `withTimeout` and grid fallback from `ui/src/layout/schemaLayout.ts`. Extract the shared worker plumbing to `ui/src/layout/elk.ts` and keep the Schema behavior and tests green.
  2. **Inside a folder,** files fill a grid of `COLS_PER_FOLDER` columns in first-seen order.
     - A new file takes the first free slot nearest to the slot of the file it has an edge with, otherwise the next slot.
     - Existing files never change slot.
     - A folder's height is computed from its rows.
  3. **Folder growth.** When a folder grows taller, folders below it in the same column are pushed down by the growth (Global Constraints). Nothing moves sideways.
  4. **Pins** override computed positions for files, and for folders at the folders level.
  5. **Removed items** are dropped from the result.
- `pins.ts`:
  - `loadPins(root): Pins`
  - `savePins(root, pins)` (debounced 300 ms by the caller)
  - `resetPins(root)`
  - `Pins = { files: Record<string, Pos>; folders: Record<string, Pos> }`
  - Storage errors return empty pins and are never thrown.
