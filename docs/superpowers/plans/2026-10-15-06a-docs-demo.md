# LiveMap Docs, License and Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A newcomer can understand LiveMap, see it working and get it running in five minutes.
- The README is a short landing page with screenshots.
- Detailed guides live in `docs/`.
- The license forbids selling.
- One command produces a scripted demo replay and the README screenshots.

**Architecture:** This plan is docs plus one script. There are no product code changes.
- **Docs move:**
  - The README's current reference sections move into `docs/guide.md`.
  - The README becomes the landing page.
  - New guides cover agents, privacy and the architecture, plus a CONTRIBUTING file.
- **Demo:** `scripts/demo.mjs` builds a temporary sample project, then starts the built CLI with a temporary `LIVEMAP_HOME`. It drives a scripted agent session through the hook endpoint, the same way `tests/e2e/agents.spec.ts` does, and writes real files on a timed schedule. It then runs `livemap export` and, with `--shots`, captures screenshots with Playwright.

**Tech Stack:** Markdown, inline SVG (text), Node ESM script, Playwright (existing dev dependency), and the built `dist/cli.js`.

**Spec:** `docs/superpowers/specs/2026-10-14-livemap-design.md`. Spec section 1 (what LiveMap is) and section 12 (privacy) are the authority for the claims the docs make. The code is the authority for flags, defaults and paths.

## Global Constraints

- **License: MIT + Commons Clause License Condition v1.0.** `LICENSE` contains the Commons Clause notice first and the MIT text below it.
  - **Commons Clause text:** exactly as follows, with straight quotes allowed:

    > "Commons Clause" License Condition v1.0
    >
    > The Software is provided to you by the Licensor under the License, as defined below, subject to the following condition.
    >
    > Without limiting other conditions in the License, the grant of rights under the License will not include, and the License does not grant to you, the right to Sell the Software.
    >
    > For purposes of the foregoing, "Sell" means practicing any or all of the rights granted to you under the License to provide to third parties, for a fee or other consideration (including without limitation fees for hosting or consulting/ support services related to the Software), a product or service whose value derives, entirely or substantially, from the functionality of the Software. Any license notice or attribution required by the License must also include this Commons Clause License Condition notice.
    >
    > Software: LiveMap
    > License: MIT
    > Licensor: Jatin Sahni

  - **MIT text:** the standard MIT text, with copyright `Copyright (c) 2026 Jatin Sahni`.
  - **package.json:** `"license": "SEE LICENSE IN LICENSE"`.
  - **Docs wording:** the docs say plainly that LiveMap is free to use, modify and share, including at work, but that nobody may sell it or sell a product or service whose value comes mainly from it. They also say the license is source-available, not OSI open source.
- **Copy:** no em dashes anywhere, US spelling ("license"), and plain direct sentences. No marketing superlatives such as "revolutionary" or "blazing".
- **Accuracy:** every flag, default, path, environment variable, exact UI string and supported-framework claim must match the code on this branch. When docs and code disagree, the code wins, and the implementer reports the mismatch. Install instructions must be true today: LiveMap is not on npm yet, so the Quickstart installs from source. Phase 6 will add `npx livemap`.
- **No secrets in images.** Screenshots use only the generated sample project and fake prompts.
- **Large files:**
  - The demo HTML (about 7 MB) and the PNGs are generated into `docs/demo/` and `docs/images/`.
  - The PNGs are committed. Keep each under 400 KB: use a deviceScaleFactor of 2, crop, and compress with Playwright's PNG output, or `sharp` only if it is already installed.
  - The demo HTML is not committed. Add `docs/demo/*.html` to `.gitignore`. The user attaches it to a GitHub Release.
- **README length:** at most about 120 lines. Anything longer belongs in `docs/`.

## Review Focus

1. **A reader following the Quickstart on a clean machine** expects every command to work as written. This covers clone, install, build, `npm link` or `node dist/cli.js`, `livemap init` and `livemap`. Task 1 verifies this by running the Quickstart in a fresh temp clone of the local repo.
2. **Docs claims drifting from the code**, such as a wrong default port, a wrong flag spelling or a stale UI string. Task 1 includes a claims check: a scripted grep of each documented flag and default against `src/cli.ts`.
3. **Demo nondeterminism** (timing races, machine speed). The demo script must wait on observable server state (`/api/history/info`), not on sleeps alone, and it must produce the same story on every run. Task 2 runs it twice.
4. **Broken links and image paths** in Markdown. Task 1 runs a link check script over README and `docs/*.md` (relative paths and anchors).
5. **The demo leaking the builder's machine paths or environment.** The export already scrubs the root, but the sample project lives in a temp dir. Task 2 asserts that the demo HTML contains no `/tmp/`, `/home/` or `/Users/` path and no environment values.

### Task 2: Demo replay and screenshots

**Files:**
- Create: `scripts/demo.mjs`
- Modify: `package.json` (`"demo": "node scripts/demo.mjs"`), `.gitignore` (`docs/demo/*.html`)
- Output, not committed by the script: `docs/demo/livemap-demo.html` and `docs/images/{hero,activity,map,schema,timeline,summaries}.png`

**Behavior:**
- **Usage:** `npm run demo [-- --shots] [-- --out <file>]`. It requires `npm run build` first; if `dist/cli.js` is missing it exits with "Run npm run build first."
- **Sample project:**
  - Copy `tests/fixtures/fullstack` (read it first; if it is too large or too small for a good story, pick the best fixture and explain why) into a temp dir named `shop` so the export says "shop". Init git there.
  - Use a temp `LIVEMAP_HOME`.
  - Start `dist/cli.js <dir> --no-open --port <free>`, then read the token the same way the e2e tests do (see `tests/e2e/agents.spec.ts` and its helpers).
- **Story:** one Claude Code session, driven through the hook endpoint the e2e tests use, so it attributes as exact. About 6 prompts over about 60 to 90 s of compressed wall time, for example:
  1. "Add order cancellation." The agent message, then tool calls that edit the service, add a route, and add a `cancelled_at` column migration.
  2. "Show cancelled orders in the admin page." Edits a React page and creates a component.
  3. "Add tests for cancel." Creates a test file.
  4. One commit.
  5. Optional: one Flag sent from the UI, using the REST endpoint the UI uses, then picked up by the agent.

  Files are really written to disk so the watcher, parsers and history record real changes. Wait on `/api/history/info` `last` increasing after each step, not on fixed sleeps alone. Keep small, fixed gaps between steps so the timeline shows rhythm.
- **Summaries:** start a fake Anthropic server, as in `tests/e2e/history.spec.ts`, that returns canned, sensible summaries keyed by path. Enable it through the temp config so the inspector and change cards show summaries. The fake must never be described as a real model output in the docs. Screenshots show it as a feature.
- **Export:** stop the CLI cleanly, run `dist/cli.js export <dir> --out docs/demo/livemap-demo.html`, and print the size.
- **`--shots`:** Before stopping, open the live UI with Playwright (Chromium at `/opt/pw-browsers/chromium` if `PLAYWRIGHT_BROWSERS_PATH` is set, else the default) at 1440x900, deviceScaleFactor 2, light theme, and capture:
  - `hero.png`: the Activity tab with the Map visible if a layout allows; otherwise the Map tab with a file selected and the inspector open.
  - `activity.png`
  - `map.png`: Files level, Follow on.
  - `schema.png`
  - `timeline.png`: rewound, banner visible.
  - `summaries.png`: inspector "In plain English", plus a change card lead.

  Wait for animations to settle using the same settle helpers the e2e specs use. Screenshots must not show any real path; the project header shows "shop" and the temp path is cropped or hidden, so check what the toolbar shows.
- **Determinism and safety** (Review Focus 3 and 5):
  - Run the full demo twice. Both runs complete, and the export opens offline: reuse the export e2e approach to load it from `file://` once.
  - The HTML contains no `/tmp/`, `/home/`, `/Users/` or `C:\\Users` and no value of `process.env.HOME`.
  - The script fails loudly on any step timeout of 20 s.

- [ ] **Step 1:** Write `scripts/demo.mjs`.
- [ ] **Step 2:** Run `npm run build && npm run demo -- --shots` twice. Expected: both runs exit 0, and the outputs exist.
- [ ] **Step 3:** Read every PNG back, iterate until each looks polished, and check that each is under 400 KB. Open the demo HTML via Playwright `file://`, scrub, and play it.
- [ ] **Step 4:** Run `npm run docs:check` (without `--allow-missing-media`). Expected: exit 0, since the images now exist and the demo is only linked through the Release URL.
- [ ] **Step 5: Commit.** Commit `scripts/demo.mjs`, `package.json`, `.gitignore` and `docs/images/*.png` with the message `feat: scripted demo replay and README screenshots`. The PNGs are committed locally; the controller hands them to the user to push.

## Rulings made while planning

- **R1:** MIT + Commons Clause, chosen by the user ("nobody can sell or resell"). It is not OSI open source, and the docs say so. Cost if wrong: a relicense later, which is easy before outside contributions.
- **R2:** The Quickstart installs from source until phase 6 publishes to npm. Cost if wrong: none.
- **R3:** The demo HTML is not committed (about 7 MB). It goes on a GitHub Release, and the README links to `releases/latest`. Cost if wrong: one dead link until the user uploads it.
- **R4:** Demo summaries come from a canned fake provider, so the demo needs no API key and stays deterministic. Cost if wrong: none.
