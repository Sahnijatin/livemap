# Changelog

This file lists changes that affect data or settings on your machine.

## Unreleased

- **Message the agent.** The inspector's Live session view has a "Message the agent" box. The message is handed to the agent when it finishes its turn, through its stop hook, and the agent carries on with it. The installed hook script changes for this: run `livemap init` again to update it.
- **Settings in the UI.** The gear button in the toolbar opens Settings. AI summaries and Ask can be turned on or off there, with the provider, model, address, token cap and API key, and take effect without a restart. Saving writes `~/.livemap/config.json` (mode 0600), keeping its other entries; the key is never shown again. Changing the provider or address removes a saved key. Guardrail rules can be added, turned off (`"enabled": false`) or removed there, which writes `.livemap/guardrails.json` in the project. The Ask tab's "AI is off" page now opens Settings.
- **Guardrails.** Rules in `.livemap/guardrails.json` in your project block an agent's tool call before it runs: `paths` (as in `.gitignore`) for files it must not write, `commands` for text in shell commands, and `action: "pause"` to pause every agent as well. LiveMap only reads this file. The inspector lists the rules and the latest blocked calls, which are also recorded in history. See `docs/agents.md`.
- **`livemap --version`** (or `-v`, `version`) prints the installed version, and `livemap help` prints the usage. A folder named `help` or `version` is now written `./help`.
- **`.git/info/exclude` is honored.** Files listed there are skipped like `.gitignore`d ones. `livemap init` lists its own hook files there, so they no longer show in the map or as the first change in the Activity feed. Restart LiveMap after editing the file.
- **Dependencies updated** for security advisories in the MCP SDK and its HTTP dependencies, used by `livemap sn` and `livemap mcp-proxy`.

## 0.2.0 (2026-11-05)

- **First public release on npm** (`npm install -g livemap`). LiveMap is free to use under the LiveMap License (see LICENSE). Requires Node 20 or later.
- **Ask tab.** Ask questions about the project, or about the open file and its connections, answered by your AI summaries provider.
- **AI summaries no longer vanish on failure.** The inspector shows why a summary could not be written and offers Try again. OpenAI requests use `max_completion_tokens`, and an empty reply is reported as an error.
- **History location can change on Windows and macOS.** LiveMap now resolves a project's real path with the operating system's own call (`fs.realpathSync.native`). On Windows this gives long names instead of 8.3 short names (`C:\Users\RUNNER~1`) and the folder's real casing; on macOS it gives the real casing. History and the project lock are keyed by a hash of that path, so a project whose path resolves differently now starts a new history in `~/.livemap/projects/`. The old folder is left in place; delete it when you no longer need it.
- **Exports on Windows include source code again.** The same path change fixes exports that held no files.
- **`BROWSER`** names the program that opens LiveMap's URL, with arguments and `%s` for the URL; `BROWSER=none` opens nothing.
- **`livemap sn`** mirrors a ServiceNow scope through SkyForge's nexus MCP (read-only) into `.livemap/sn/` and shows it in the Map, Schema and API views. Business rules, client scripts, UI policies and ACLs show as rules on their tables.
- **`livemap sn` imports the scope's history** to `.livemap/sn/<scope>.history.json`: dated events from `sys_update_version` (or `sys_update_xml`), matched to SkyForge's MCP log where a tool call on the same instance names the record.
- **`livemap sn` follows live changes.** While the UI runs it reads the instance every 5 seconds (`--poll`), updates the mirror and shows each change with its diff. Deletes are applied, the instance clock skew is learned, and the status chip says when the instance is offline. Its position is kept in `.livemap/sn/<scope>.state.json`, and new saves join the scope's history file. Each record's files now say which update set, user and time last changed it.
- **`livemap sn` works with real nexus.** It no longer stops with `raw.normalize is not a function` while pulling: reference fields that nexus returns as `{link, value}` objects are read as their value.
- **`livemap mcp-proxy`** lets LiveMap see the tool calls of a desktop MCP client. The client's nexus entry launches the proxy, which forwards everything unchanged and reports each call, with secrets redacted, to `livemap sn`. Instance changes are matched to calls by record, update set, run window and time, with confidence `exact`, `likely` or `ambiguous`.
- **SkyForge plugin.** `livemap sn install-plugin` copies LiveMap's plugin into `~/.skyforge/plugin/` after a yes at a prompt (`--uninstall` removes it). It reports SkyForge's nexus tool calls, prompts and assistant text to `livemap sn`. `livemap sn backfill-sessions --since DATE` sends past SkyForge sessions the same way.
- **ServiceNow inspector, filters and diagnostics.** In a `livemap sn` project the inspector shows each record's update set, last update, what it uses, the latest change's confidence and why, and an Open in ServiceNow link. A filter bar (scope, update set, session, agent or human, confidence) narrows the Map, Schema, Activity and diffs, and is kept in the page address. The toolbar counts unattributed changes, and Unknown tools lists tools LiveMap could not classify. See `docs/servicenow.md`.
- **Third-party notices.** The build writes `THIRD_PARTY_NOTICES.md` to `dist/`, `dist/ui/` and `dist/ui-export/`, and CI fails when a shipped package has a license outside the allowlist.
- **ServiceNow history in the timeline.** `livemap sn` adds the scope's version history to the timeline as a back-dated run before the live one, once per scope, so rewind shows the scope growing from its first saves. Saves that matched no tool call carry the user who saved them, not an attribution. The import is noted in `imports.json` in the project's history folder, with its import format, a hash of the history file and its newest save. A newer import format rebuilds the run once and resets the project's recorded timeline: every recorded run is deleted, and the whole history is imported again as the first run.
- **ServiceNow history attribution on real data.** A call's instance is now known when only that instance connected in the 7 days before it, since SkyForge processes run for days. A call that names the record's sys_id, or a record on one of the scope's tables, gives `log` even when its instance is unknown. Records whose versions were rewritten later get their creation from their own stamps, and a bulk rewrite of more than 100 versions by one user within 10 minutes shows as an update set commit, its deletes included. With no SkyForge log at all, any such burst counts as a commit, since there is no log to show SkyForge was busy then. Field labels (`sys_documentation`) and form sections now match the calls that made them. The next `livemap sn` run rewrites the history file. A timeline that already imported the scope's history is rebuilt from it on the next start, since the import format changed (see above).
- **CI** runs the unit tests on Windows (Node 22) as well as Ubuntu and macOS.
